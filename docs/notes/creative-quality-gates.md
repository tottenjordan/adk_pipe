# Creative quality gates — detailed rules

Reference for the deterministic checks, the post-render image QA and the eval gates added by
the 2026-10-07 creative-quality work (PRs #263–#280). `CLAUDE.md` keeps the summary; this
note keeps the calibrated details that matter when you change a heuristic. Plan:
[docs/plans/2026-10-07-creative-quality.md](../plans/2026-10-07-creative-quality.md).
Research: [docs/research/2026-10-07-creative-quality.md](../research/2026-10-07-creative-quality.md).

All of these are deliberately **conservative**: a false failure costs a revision round or a
re-render (against the ~2 RPM image quota) and erodes trust in the gate, so each rule was
tuned on live runs to flag only clear problems (false-positive fixes: #268).

## Concept guard + concept gate (`creative_agent/concept_guard.py`, `text_match.py`)

"Missing" (motif, product and brand cue alike) is token overlap, not a substring (`creative_agent/text_match.mentions`: the full phrase, or ≥60% of its content tokens, plural/accent-insensitive; size tokens and a size's container ("16oz can") ignored, a packaging head noun ("iPhone case") required; a single-token phrase needs its full core ("Pixel 9"); with a brand, the brand plus every distinctive token (a digit or all caps in the original phrase) counts regardless of the ratio, so "PRS SE CE24" names "SE CE24 Electric Guitar" (packaging head noun still required; the brand-less motif check never uses this rule); brand-anchored — a partial product/brand-cue match must include a brand token, unlike the copy gate where naming the brand counts); intangible products (subscription/app/service/insurance…) get a softer branded-screen/logo cue, skipped when the brand is mentioned. `concept_gate` then runs `concept_guard.concept_issues` (deliberately conservative string heuristics — only a double-quoted span with a text cue ≤6 words before it counts as in-image text (2026-10-08 added quote/quoted/quotes/phrase/wording/inscription/inscribed; the often-descriptive painted/neon/bearing/displays/displaying count only directly before the quote, so "painted in warm \"golden hour\" tones" stays descriptive), idioms like "sign of", "title of", "poster style", "vibe reads" excluded; only copy-matching text concepts count toward the cap (mismatches get their own issue); meme/comic concepts are exempt (style contains "meme" or a meme/comic family, or the prompt says meme caption/speech bubble|balloon/thought bubble/comic panel/top|bottom text/Impact font); a bare "centred" needs a subject/composition word, and the centred-hero check skips "off-centre", "centred between", "camera centred on", "… third" placements and sentences about text/logos) and routes flagged concepts to one bounded `visual_concept_fixer` round (`CONCEPT_REVISION_ROUNDS`, default 1, clamped 0–2).

## Post-render image QA (`creative_agent/image_qa.py`)

`image_tools.generate_image` inspects every render with one structured vision call (`creative_agent/image_qa.py` `inspect_image` → `ImageQAResult`, model `IMAGE_QA_MODEL`, default the worker model, temperature 0, global client with HTTP retry + the shared timeout). **Conservative by design** (every false failure costs a re-render against the ~2 RPM image quota; calibrated on live renders): the QA instruction includes the concept's `image_generation_prompt` (capped at 1500 chars) as "What the image was asked to show"; `product_visible` accepts a recognisable partial/close-up view (an intangible product or abstract motif counts when the prompt's depiction is present); `gibberish_text` covers only prominent, readable-size garbled lettering (tiny/blurred background text and stylised renderings of the brand's own logo don't count; meme/comic slang spelling is exempt); `unrequested_logos` only clearly recognisable marks of brands other than the campaign brand, the product's maker, any brand named in the prompt/its quoted text, the `brand_cue` and a logo reference image. The pure rule `qa_failed_rules(result, concept, target_product=…)` fails an image on: product or trend motif not visible (skipped when `target_product` / `trend_motif` is empty), a malformed product (`product_malformed`, default `False` so older payloads parse: mirrored/reversed, parts missing/duplicated/misplaced, warped or melted; skipped without a product; not a critical rule; correction "render the product with its correct real-world shape and orientation"; added 2026-10-08 after a backwards guitar passed), gibberish text, an unrequested logo, noticeable artifacts (softened from "severe" 2026-10-08; the rule name stays `severe visual artifacts`), unsafe content, or required in-image text not exact/legible — `expected_text` (= `concept_guard.in_image_quotes`) is authoritative; the model's `text_expected` only counts for a meme/comic concept whose prompt quotes text. A missing `brand_cue` is advisory. A failing image is re-rendered at most `IMAGE_QA_MAX_RERENDERS` times (default 1, clamped 0–2) and at most `IMAGE_QA_MAX_RERENDERS_PER_RUN` times across the whole call (default 2, clamped 0–8; when hit, the image's `image_qa__issues` entry gets "(re-render budget reached)"), with `image_qa.correction_text` appended (the model's problem statements with quote characters stripped, each ≤120 chars — fixed rule phrases when a text rule failed — always ending "Do not add any new text to the image."; same references / aspect ratio, through the quota-paced backoff, whose sync genai call runs via `asyncio.to_thread`). Keep-decision: compare (critical failures — `unsafe`, `unrequested_logos` — then total) lexicographically, ties → latest, and never keep a retry that introduces `unsafe`; only the kept image is uploaded. `IMAGE_QA_ENABLED=false` is the kill switch (single render, no QA calls). All four knobs live on `BaseAgentConfiguration` and ship via `deploy_agent.py` `ENV_VAR_DICT` (read at import: Agent Engine bakes in the deployer's env). Fail-open: a QA error keeps the render (`qa: None`) and lists the concept in `image_qa__unavailable` — deliberately not an `__issues` key, so `collect_degradation_warnings` (which only surfaces `__issues`/`__retry_exhausted`) doesn't report it as an unresolved issue. Results: `state["generated_images"] = {concept_name: {gcs_uri, artifact_key, attempts, qa}}` (`qa` = verdict fields + `passed` + `failures` (the model's problem statements, else rule names), None when disabled/unavailable; `_generated_artifact_keys` unchanged); still-failing images go to `image_qa__issues` (→ `collect_degradation_warnings`); the HTML gallery shows a per-image "Image check" line and the results proof detail an "Image check" row.

## Eval gates (`creative_eval/`)

The judge answers a judge-only schema (`AdCopyJudgeOutput` / `VisualJudgeOutput`: `gates` required, min 1; no `overall_score`/`passed`/`gates_passed`/`advisory`/`image_judged` — code maps it to the report models and computes those). Gate prompts: presence gates pass only when clearly present, violation gates (`avoid_respected`, carryable `mandatories_met`, `no_visual_defects`, `trend_risks_respected`) fail only on a clear violation, not-applicable passes with the reason in the note. Gates are normalised in code (`normalize_gates`: none of the expected gates reported → one failed `gates_reported` gate, "judge returned no gates"; a partial omission passes as "not checked" and adds a report warning "N checks not reported by the judge"; without a brief the brief-dependent gates pass with note "no brief" and `report.brief_used=False`). The visual judge sees the **rendered image** (`generated_images[concept].gcs_uri` as a `gs://` `Part`; the prompt is only intent; the image-QA verdict is a hint line) (fetched by the Vertex AI service agent; cross-project buckets need it granted `storage.objectViewer`) — no image, or an image read error (403/404, or a 400 mentioning the image/URI/file/permission; other 4xx are normal judge failures), falls back to judging the prompt (`image_judged=False`; the fallback adds a report warning).

## Brand history (`creative_agent/brand_history.py`)

`load_brand_history` (function node, no LLM) runs in `combined_research_pipeline`'s START fan-out next to the two planners and feeds `research_join`. It reads the brand's latest `BRAND_HISTORY_RUNS` (default 5, clamped 0–20) `creative_evals` rows (parameterised SELECT, case-insensitive brand match) plus their eval-report JSON (configured bucket only, 5 MB cap), and writes `brand_history` — a brace-free ≤120-word note (recent styles, strongest styles/copy tones, recurring weak dimensions, often-failed gates) read via `{brand_history?}` by the brief writer and art director. Unless `visual_style_preference` is set, it re-draws `style_shortlist` without the recently used styles (`pick_style_shortlist(exclude=...)`, 2/3/1 strata kept). Fail-soft: 10 s timeout in a worker thread, any error → `""`; `BRAND_HISTORY_ENABLED=false` skips it (no query). Eval report entries now carry `visual_style` / `angle_id` (code-set, `""` in old reports); angle ids are per-brief so only styles and copy tones are aggregated. The `creative_ratings` table is not joined (no clean run key). Only allowlisted values reach the prompts: report styles are mapped to canonical `STYLE_GROUPS` families (`style_shortlist.canonical_style`, unmapped dropped), tones must be in the `tone_style` Literal, weaknesses known dimension labels, checks known gate names. History spans **all users** of a brand (`creative_evals` has no user column; shared artifacts are expected under P3), and the brand match is exact after trimming and case-folding ("Acme" = "acme", but not "Acme Inc").

### 2026-10-08 gate changes (rater audit)

A live audit found the judge passed 16/16 creatives that a human failed 8/16 (trend unclear,
rendering defects incl. a mirrored guitar, off-brief, jokes about a real "Category 4"
hurricane). Three judge changes, all blocking:

- `no_visual_defects` (visual, "No visual defects"): the product is physically correct (right
  shape, parts in place and orientation, not mirrored/duplicated/melted/merged) and anatomy
  and geometry are normal; deliberate stylisation (cartoon, comic, collage) is exempt.
- `trend_risks_respected` (ad copy + visual, brief gate, "Respects trend risks"): the brief's
  `trend_bridge.risks` now reach the judge as a `Trend risks: a; b` line (omitted when there
  are none); the creative must not make light of, exploit or sensationalise those harms. No
  risks listed → pass; no brief → passes "no brief".
- `trend_motif_visible` is stricter: the motif must be prominent and recognisable at a glance
  as a reference to the campaign trend without reading any copy; tiny, background, generic
  ("any storm", "any phone screen") or merely implied motifs fail.

Judge pass rates and `gates_pass_rate` before and after this change are **not comparable**.
