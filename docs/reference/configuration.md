## Shared building blocks (`agent_common/`)

Shared building blocks live in **`agent_common/`** (a lightweight package bundled into every deployed engine; it depends on `google-adk` but is deliberately free of any per-agent business logic, and no cloud function imports it):
- `agent_common/config.py` — `BaseAgentConfiguration`, the single source of truth for what every agent reads: model names, rate-limit knobs, `trend_timezone` and GCP/BigQuery env vars, plus `parse_on_flag` (the shared on-unless-0/false/no/off env flag parser). Each agent's `config.py` subclasses it (`ResearchConfiguration(BaseAgentConfiguration)`) and adds only the knobs that agent reads (`trend_scout`: gather/picker models, `trend_digest_enabled`, `BQ_TABLE_TREND_DIGEST`; `creative_agent`: image QA/render knobs, `image_size`, `image_aspect_ratio_default`, the fixed `image_aspect_ratios_allowed` set (also read by `runserver.share_snapshot` / `runserver.variants`), `BQ_TABLE_RATINGS` and its revision/brand-history/rating/person/timely knobs), which is why the agent configs no longer drift; code reads them as `config.X` either way.
- `agent_common/retry.py` — `build_infra_retry(extra_exceptions=(), max_attempts=3)`, the one place the ADK `RetryConfig` transient-exception list is defined (`creative_agent` and `trend_scout` pass the genai `ServerError`; ADK matches names against the exception MRO, so subclasses match too).
- `agent_common/retry_node.py` — `RetryUntilKeyNode`, the retry-on-empty graph wrapper (a `BaseNode` that re-runs a flaky `google_search`+thinking producer child — usually a searcher → synthesizer `Workflow` — until its `output_key` is populated, bounded; a transient child exception (`is_transient_error`: 429/RESOURCE_EXHAUSTED, 499/CANCELLED, genai `ServerError`, `TimeoutError`, unwrapped from `DynamicNodeFailError`) counts as a missed attempt after a 15 s → 30 s capped backoff (≤ 45 s added per node; `retry_on_transient=False` opts out; incident 2026-10-13: a 429 from `campaign_web_searcher` failed `creative_pipeline`), any other exception still propagates; on exhaustion leaves the key unset, records `<key>__retry_exhausted`, and still yields a truthy notice so a `NodeTool` caller never stalls; a later success clears a stale marker to `None`, which every reader treats as clean), plus `is_populated(value)`, the shared populated-check (also used by `creative_agent`'s truthy terminal nodes). Shared here so every agent wraps producers without cross-importing another agent's package.
- `agent_common/fail_soft_node.py` — `FailSoftNode`, the fail-soft wrapper for *optional* graph steps (RetryUntilKeyNode retries only empty output and transient errors; any other exception propagates and fails the Workflow): runs the child once and turns an exception (unwrapped from ADK's `DynamicNodeFailError`) into a logged error + `on_error(state_before, exc)` state delta, then yields a truthy notice so successors run. Used around `creative_agent`'s brief writer (→ `creative_brief__retry_exhausted`) and reviser (keeps the pre-revision brief, → `creative_brief__issues`).
- `agent_common/schemas.py` — `PipelineRequest`, the `input_schema` (`request: str`) that gives a graph `Workflow`/node exposed as a `NodeTool` the same model-facing declaration `AgentTool` had.
- `agent_common/genai_retry.py` — `build_genai_http_retry()`, the status-code-based genai HTTP retry (429/500/503/504 with backoff; permanent 4xx fail fast), wired into `build_gemini()` and the `creative_eval` judge client; ADK-free. Also the single source of truth for the **per-request model timeout** `MODEL_REQUEST_TIMEOUT_SECONDS` (env, default 240, clamped 30–900, `0` disables; read at import, so for Agent Engine the deployer's env is pickled in) — `model_request_timeout_ms(model_name=None)` gives genai's `HttpOptions.timeout` (MILLISECONDS), applied to every agent model (via `build_gemini`, incl. both `FallbackModel` delegates), the judge client, the image-QA client and the image-gen client. It is **model-aware**: a flash/lite model (`is_flash_model`: name contains `flash` or `lite`) gets `FLASH_MODEL_REQUEST_TIMEOUT_SECONDS` (env, default 90, same clamp, never longer than the general timeout; `0` → the general timeout) — agent flash models and the image-QA client; Pro models, the judge and image gen (renders can be slow) keep the general one. Vertex also gets the timeout as `X-Server-Timeout`, so a server-side 504 DEADLINE_EXCEEDED is retried by the genai HTTP retry, a client-side aiohttp `TimeoutError` by `TimeoutRetryingGemini`. Sync httpx clients (judge, image gen): `httpx` timeouts are retried by genai `retry_options` (judge) / `_generate_image_with_backoff` (image).
- `agent_common/rate_limit.py` — `build_rate_limit_callback(config)`, the shared `before_model_callback` enforcing each agent's `rpm_quota`.
- `agent_common/sanitize.py` — `scrub_lone_surrogates` / `scrub_surrogates_in_response` (`after_model_callback`), which strip lone Unicode surrogates from model JSON before `output_schema` validation, and `build_invalid_reply_dropper(schema)` (`after_model_callback` for an optional schema'd producer under a `RetryUntilKeyNode`: runs ADK's own `validate_schema` and blanks a failing reply in place, so ADK skips it like an empty final chunk instead of raising out of the run).
- `agent_common/history.py` — `drop_other_agent_context`, the `before_model_callback` (ahead of the rate limiter) on the `creative_agent`, `interactive_creative` and `trend_scout` roots. ADK 2.10 replays every session event onto a root (branch `None` matches every branch), so each earlier NodeTool pipeline's sub-agent turns (user-role `OTHER_AGENT_CONTEXT_PREAMBLE` "For context: … [agent] said:" contents) and node inputs (user-authored events on the node's branch) piled up in the root's prompt (~33.5k tokens before the empty turns of 2026-10-07); only the latest call's interior is hidden by ADK, and NodeTool has no isolation option. It drops exactly those, keeping user messages, the root's turns and all function call/response pairs (incl. checkpoint responses). Matches ADK's private `_fencing` preamble constant; `tests/test_root_history.py` runs a real root through two pipelines, so an ADK change fails loudly. On `trend_scout` only the NodeTool-run `understand_trends_agent_resilient` and `trend_digest` (on a cache miss: its describe searcher / synthesizer and classifier) leak (plain `AgentTool` runs its agent in a fresh in-memory session, so gather/pick never reach the parent session): measured 4 extra contents (2 sub-agent transcripts + 2 node inputs) on the root's final request, 0 with the trim (`tests/test_trend_scout_history.py`).
- `agent_common/state.py` — the shared `memorize` ADK tool (re-exported from each agent's `tools.py`; the tool name must stay `memorize`) and `seed_initial_state(...)`, the one-time session-state seeding behind each agent's `callbacks._set_initial_states` (per-agent output dir / extra keys / `setdefault` defaults stay local). It also `setdefault`s the run's date keys (`timezone=config.trend_timezone`).
- `agent_common/clock.py` — per-run date state: `date_state(tz)` → `current_date` (YYYY-MM-DD), `current_datetime` (ISO with offset), `current_timezone`, `current_weekday`, seeded once per run by `seed_initial_state` — never at import (Agent Engine pickles the agents at deploy time); `setdefault`, so a resumed session keeps its original run date. Timezone `TREND_TIMEZONE` (`BaseAgentConfiguration.trend_timezone`, default `America/New_York`; unknown → default with a warning; in `ENV_VAR_DICT`; `tzdata` is a dependency). `DATE_CONTEXT_LINE` ("Today is {current_date?} ({current_weekday?}, {current_timezone?}). Interpret …") is spliced into trend_scout's searcher + synthesizer, the trend researcher's planner / searcher / synthesizer and the brief writer, ad copy drafter + critic and art director (`tests/test_date_prompts.py`).
- `agent_common/clients.py` — `get_gcs_client()` / `get_bigquery_client()`, the shared lazy client getters (SDK imports inside the functions; the BigQuery client is cached per thread via `threading.local`, never built at import, `reset_bigquery_client_cache()` for tests). Agent modules bind them to their `_get_gcs_client` / `_get_bigquery_client` names (the test monkeypatch points); `creative_agent.gcs_tools` wraps its GCS getter in `functools.cache`.
- `agent_common/idempotency.py` — `stable_row_id(*parts, length=8)`, a deterministic (`json.dumps`-framed sha256) row key. The BigQuery write tools derive their row keys from `tool_context.session.id` with it (never uuid4) and write via `MERGE … WHEN NOT MATCHED THEN INSERT`, so at-least-once tool execution (resumed apps, CRF retries) leaves exactly one logical row (the `creative_evals` row also `WHEN MATCHED THEN UPDATE`s, so a re-run's row matches its re-written GCS report JSON).
- `agent_common/safety.py` — `build_safety_plugins(root_agent_names)`, the opt-in Model Armor plugin list every agent's `App(plugins=...)` is wired with (`[]` unless `MODEL_ARMOR_TEMPLATE` is set; `MODEL_ARMOR_RESPONSE_TEMPLATE` override; fail-closed unless `MODEL_ARMOR_FAIL_CLOSED=false`). `ScopedModelArmorPlugin` screens only the root orchestrator's turns — `AgentTool`/`NodeTool` propagate App plugins into every sub-agent run. Read at agent-module import, so for Agent Engine it's the *deployer's* env that is baked into the pickled App. `creative_agent/__init__.py` re-exports `app` so ADK's canned loader serves the App, not the bare `root_agent`.
- `agent_common/locations.py` + `agent_common/models.py` — `MODEL_LOCATION` (default `global`) and `build_gemini(name)`, which pin every gemini-3.x call's serving location in code (Agent Engine *reserves* `GOOGLE_CLOUD_LOCATION`, so it can't be forced via deploy env vars). `build_gemini` returns a `TimeoutRetryingGemini` (a `Gemini` subclass): it sets the timeout per request on `llm_request.config.http_options.timeout` (not via `client_kwargs`, which would clobber ADK's headers/`retry_options`) and retries a timed-out request up to `TIMEOUT_RETRY_ATTEMPTS` (3 total) before any output is yielded — needed because ADK's async genai client uses aiohttp, whose timeout surfaces as builtin `TimeoutError`, which genai's `HttpRetryOptions` does not retry. An exhausted `TimeoutError` carries no HTTP status, so `FallbackModel` does **not** fail over on it (429/5xx only); it propagates (node `RetryConfig` lists `TimeoutError` where set). The three root orchestrators also pass `empty_turn_retries=ROOT_EMPTY_TURN_RETRIES` (2): a clean empty turn (`STOP`, no text/function call — a Pro root sometimes answers a long NodeTool result that way, and ADK then ends the invocation) is re-asked inside the model call, so it is covered under `adk eval` and Agent Engine too, not only by the runserver auto-continue (which stays the backstop). Non-streaming only; sub-agents don't opt in.
- `agent_common/observability.py` — the shared debugging callbacks used by every agent: `log_run_start` (run→session correlation line; the user only as `stable_row_id(user_id)`, never the email), `log_empty_turn_finish_reason` (`after_model_callback` that warns only on empty/abnormal producer turns), `make_final_state_summary(label, keys)` (factory → `after_agent_callback` logging load-bearing state keys + `*__retry_exhausted` markers), and `collect_degradation_warnings(state)` — the single source of truth that turns the generic `<key>__retry_exhausted` and `<key>__issues` (list/str of residual quality issues → "<Label> has unresolved issues: n (e.g. …)", capped) markers into the notes surfaced on the eval report (`warnings`), the `creative_evals.research_gaps` BQ column (legacy name: it holds **all** run notes — research gaps, failed saves, quality-check residuals, judge notes — not only research; deliberately not renamed), and the HTML gallery "Run notes" banner (HTML-escaped). Issue notes use the small display-label map `_ISSUE_LABELS` (e.g. `image_qa` → "Image check", persistence keys → "… save"; unknown keys sentence-cased); the results page groups the notes with `frontend/src/lib/run-warnings.ts` `classifyWarnings` into research / saves / quality notices, so a quality flag never shows under the research banner. Snapshots `state.to_dict()` before scanning (an ADK `State` isn't directly iterable).

## Key settings

The bucket name comes from `GOOGLE_CLOUD_STORAGE_BUCKET` (the var deploy actually ships) — not the local-only `GCS_BUCKET_NAME`; the `gs://` form (`GCS_BUCKET`) is derived from it (there is no `BUCKET` env var). Key settings:
### Models

- **Models**: `gemini-3.8-flash` (worker), `gemini-3.1-pro-preview` (critic + `creative_eval` judge — no GA Pro yet), `gemini-3.5-flash-lite` (lite planner), `gemini-3.5-flash` (creative_agent campaign research, see below; `trend_scout` `picker_model`), `gemini-3.1-flash-lite` (`trend_scout` `gather_model`), `gemini-nano-banana-2.1` (image gen; was `gemini-3.1-flash-image` until 2026-10). The 2026-09 refresh retired every gemini-2.5 agent model (Vertex shuts 2.5 down Oct 2026–Mar 2027); `trend_scout` still fans its 5 agents across 5 distinct base-model buckets, now all @ `global`.
### Pro-producer failover

- **Pro-producer failover**: the five `critic_model` producers (`creative_agent` root / `combined_report_composer` / `combined_web_evaluator`, `interactive_creative` root, `trend_scout` root) fail over to `worker_model` (`gemini-3.8-flash`, never `ALT_GLOBAL_MODEL`) on 429/5xx via ADK `FallbackModel` (`agent_common.models.build_gemini_with_fallback`; both delegates global-pinned `build_gemini` instances, primary HTTP retry attempts=2 so failover fires in ~10s). Target is `BaseAgentConfiguration.critic_fallback_model` (`CRITIC_FALLBACK_MODEL`); kill switch `CRITIC_FALLBACK_MODEL=""` returns the plain Pro model — on Cloud Run it is read at service start, but on Agent Engine the agent is pickled at deploy time, so the deployer's local env decides (redeploy with `CRITIC_FALLBACK_MODEL=""` to disable there). The `creative_eval` judge and image gen have no fallback (direct genai calls; a silent judge swap would skew pass rates) — the eval report records `judge_model` instead.
### Model location

- **Model location**: gemini-3.x models are only served from the `global` Vertex location — set `GOOGLE_CLOUD_LOCATION=global`. Regional resources (BigQuery, GCS, PubSub, Agent Engine) stay in `us-central1`.
  - **Agent Engine region (`GCP_REGION`):** Agent Engine / Reasoning Engine is a *regional* resource, so its Vertex AI SDK clients read `GCP_REGION` (default `us-central1`), decoupled from `GOOGLE_CLOUD_LOCATION=global`. Wired through `deployment/deploy_agent.py`, `deployment/test_deployment.py`, `deployment/integration_test.py`, and the `cloud_functions/*/config.py` constants (`config.GCP_REGION`). The `global` model location is used only by the genai model clients (`creative_agent/image_tools.py`, `creative_eval/judge.py` — the eval judge defaults to `MODEL_LOCATION`, overridable via `EVAL_MODEL_LOCATION`) plus the ADK agents' `build_gemini()` models; BigQuery and GCS clients take no location.
### Rate limiting

- **Rate limiting**: async `before_model_callback` enforces rpm_quota (1000) over 60s intervals (`await asyncio.sleep`; counters under `temp:` keys, so they reset per invocation and are never persisted)
### Cloud Trace

- **Cloud Trace (opt-in)**: api `ADK_OTEL_TO_CLOUD=true` → `get_fast_api_app(otel_to_cloud=True)` (`runserver/otel.py`); pair with `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false` (ADK defaults it on). Engines: `deploy_agent.py --enable_tracing`. IAM/runbook: deployment/README.md §9.
### Campaign-research placement

- **Campaign-research placement (`CAMPAIGN_RESEARCH_PLACEMENT`)**: selects which model bucket the `campaign_researcher` sub-agent runs on, via `ResearchConfiguration.campaign_models()` in `creative_agent/config.py`. Default `global_altbucket` runs campaign research on `ALT_GLOBAL_MODEL` = `gemini-3.5-flash` @ `global` — a different per-base-model quota bucket from the trend half's `gemini-3.8-flash`/`gemini-3.5-flash-lite` (the PR #101 spread that halves contention in the research fan-out). Alternate arm `global_3x` shares the trend buckets (comparison baseline); unknown values (incl. the retired `regional_25` gemini-2.5 arm) fall back to the default — see `experiments/quota_spread/` and [experiments/README.md](../../experiments/README.md). Leave unset for production behavior.
### Temperature profile

- **Temperature profile (`GEMINI_TEMPERATURE_PROFILE`, `agent_common/sampling.py`)**: `tuned` (default) keeps every agent's hand-tuned `temperature`; `default` sets every agent that has one to the Gemini 3 default 1.0 (Gemini 3 docs advise against lower values); unknown → `tuned` + a warning. The seam for the temperature A/B (`docs/plans/2026-10-15-gemini3-temperature-ab.md`). Read at agent-module import (Agent Engine pickles the deployer's value; Cloud Run reads it at revision start; shipped in `ENV_VAR_DICT` + `deploy.env`); not the `creative_eval` judge or image QA. `tests/test_temperature_profile.py` pins the tuned golden. **A/B result 2026-10-15: keep `tuned`** (rule FAIL: the 0.0 sensitivity classifier lost flag stability at 1.0 (agreement 0.92 vs 1.00) and gates_pass_rate fell −0.19 at n=4; zero empty/abnormal turns in either arm; `docs/experiments/2026-10-15-gemini3-temperature-ab.md`).
### Post-render image QA

- **Post-render image QA (on by default)**: `image_tools.generate_image` (called directly by the `visual_generator_resilient` function node, no LLM wrapper turn; every render prompt ends with the no-other-logos line) inspects every render with one structured vision call (`creative_agent/image_qa.py` `inspect_image` → `ImageQAResult`, `IMAGE_QA_MODEL`, temperature 0). The pure rule `qa_failed_rules` fails an image on: product not visible, trend motif not visible (visible and recognisable as the trend, stylised/symbolic references counting, like the judge's `trend_motif_visible`; prominence only under `trend_unclear` strictness), a malformed product (`product_malformed`: mirrored/reversed, parts missing/duplicated/misplaced, warped; not critical), an off-model product (`product_off_model`: drawn as a generic object losing its real silhouette/shape; recognisable stylisation and a missing/simplified label exempt; not critical), prominent gibberish text, an unrequested (other-brand) logo, malformed hands (`hands_malformed`: every visible hand's fingers counted — extra/missing/fused, wrong-side thumb, two left/right hands, a hand merged into an object; consistently simplified hands in a clearly illustrated style exempt, photographic never; not critical), noticeable artifacts, unsafe content, or required in-image text (`concept_guard.in_image_quotes`) not exact/legible; a missing `brand_cue` is advisory. A failing image is re-rendered with `image_qa.correction_text` appended at most `IMAGE_QA_MAX_RERENDERS` times (and ≤ `IMAGE_QA_MAX_RERENDERS_PER_RUN` per call, through the quota-paced backoff); the better attempt is kept (critical failures `unsafe`/`unrequested_logos` first, then total; never a retry that introduces `unsafe`) and only it is uploaded. **Pipelined:** at most `IMAGE_RENDER_CONCURRENCY` image-model calls are in flight behind one `asyncio.Semaphore` (image quota; re-renders count toward the cap); first renders are staggered by concept (concept i waits for concept i−N's first render, so the first N start at once), and each image's QA (+ its re-render) runs as a task while other concepts render; a re-render queued while every slot is busy takes the next free slot (FIFO, usually ahead of later first renders); N=1 is the old strictly sequential pipeline; the per-run budget is still claimed in concept order (`claim_after`/`claims_done` event chain), and uploads happen afterwards, up to `UPLOAD_CONCURRENCY` (4) in parallel, started and recorded in concept order (kept image only; a failed render uploads nothing). A concept whose render raises after the backoff is skipped with an `image_qa__issues` entry "<concept>: render failed: …" while the others render and upload; only when every concept raised does the error propagate (`INFRA_RETRY`). Artifact keys are de-duplicated per call (`gcs_tools.unique_artifact_keys`: "Game Day!" and "Game Day" → `Game_Day.png` / `Game_Day_2.png`; readers take the record's `artifact_key` via `record_artifact_key`). The idempotency marker `_images_generated` is a render fingerprint (`render_fingerprint`: concept names, prompts, cast flags + the person reference), so a re-run with changed concepts renders again (a legacy `True` still skips), and the render step re-applies `enforce_timely_cap` next to `enforce_person_casting`. `IMAGE_QA_ENABLED=false` = single render, no QA calls. With `safer_angle_active` ("yes", a sensitive trend's safer angle) the QA call adds one question → `public_figure_likeness` (rule "real public figure likeness", **critical**; correction "show the theme through instruments, era and setting, never the real person's likeness"; stored only then — otherwise the request schema/instruction and records are unchanged, render parity golden). Fail-open: a QA error keeps the render (`qa: None`) and lists the concept in `image_qa__unavailable` (deliberately not an `__issues` key). Results → `generated_images`; still-failing images → `image_qa__issues`; shown as "Image check" in the HTML gallery and the results proof detail. Calibrated heuristics: [docs/notes/creative-quality-gates.md](../../docs/notes/creative-quality-gates.md).

### Trend situation

- **Trend situation (the trend's current moment, `TREND_STATE_RESEARCH.md` Idea 2; plan `docs/plans/2026-10-11-trend-state-awareness.md` PR 2)**: `trend_situation_pipeline` (`creative_agent/sub_agents/trend_situation/agent.py`) runs in `combined_research_pipeline`'s START fan-out beside the planners and `load_brand_history` (the join waits for it). `trend_situation_gate` routes `skip` when `TREND_STATE_ENABLED=false` (no model call) and clears a stale `trend_situation_draft` on both routes; `run` = a `FailSoftNode` around a `RetryUntilKeyNode` (2 attempts) over a grounded `trend_situation_searcher` (google_search, date-aware via `agent_common.clock.DATE_CONTEXT_LINE`; `collect_trend_situation_sources_callback`: its sources join `sources` as `src-N`, and only this searcher's own sources (this invocation; `source_ids_by_agent`) go to `trend_situation_sources`) → `trend_situation_synthesizer` (reads `{trend_situation_sources?}`, never the whole `sources` dict; `output_schema=TrendSituationDraft`: `phase` upcoming|live|just_happened|ongoing|evergreen|sensitive|unknown, `event_name`, `event_start`/`event_end` ISO, `outcome` win|loss|draw|other|none (from the side the target audience supports; neutral/unclear → the first-named subject), `outcome_summary`, `audience_sentiment`, `source_ids`, `confidence`). (a vision-LLM comparison, no face embeddings); rules "person likeness lost" / "person distorted" / "person shown as a public figure" (correction "show the person as themselves, not as a public figure") (none critical; no tattoo/skin-marks check — removed 2026-10-12 because a reference person's real tattoos were flagged) feed the bounded re-render, whose correction restates the likeness instruction. **Judge:** the `person_depicted_respectfully` gate in [evaluation.md](evaluation.md). **Results page:** the proof detail shows "Cast: Yes — <reason>" or a "Person photo rejected by the safety filter; this image was made without the person." note. **Shares** (plan PR 4): a cast concept is shared only when its `consent_id` is an active consent of the share owner with `allow_public_share` (see Person share scope + revoke cascade). A cast concept whose judge omits `person_depicted_respectfully` fails it with note "not checked" (plus a report warning). Cast creatives can be bandit-experiment arms while their consent is active (see Personalised variants).
### Personalised variants

- **Personalised variants (`person_variants`, plan PR 3, UI only)**: the results proof dialog's **Personalise** panel (`components/personalise-panel.tsx`, shown for rendered creatives; `lib/variants.ts` `canPersonalise`) makes a variant of one finished concept with one of the caller's consented people as the hero, by **editing the original render** (edit mode, plan `docs/plans/2026-10-11-faithful-person-swaps.md`; spike `docs/notes/person-swap-edit-mode.md`: edit fidelity 75% vs 0% for a fresh render). A creative that already casts a person is a **person swap** (plan `docs/plans/2026-10-11-person-swap.md`): the panel reads "Swap person" and leaves the cast person out of the picker (only them registered → Render disabled with "Register another person on the People page to swap."); the edit replaces only the main person, so a swap is derived from the cast person's image and is recorded on **both** consents (see below). `POST /variants/{user}/{app}/{session}` (`runserver/variants.py`, body `{concept_name, consent_id}`; creative apps only; session ownership like `/shares`, foreign → 404) requires `person_refs.active_consent` (else 400 `consent_not_active`), no live run for the session (409 `run_in_progress`), a finished run (`finalize_done`) with a rendered base image for the concept (409 `concept_not_ready`), the concept in `final_visual_concepts` (400 `concept_not_found`), castable by `enforce_person_casting` (person-safe style + a human subject — the variant's own hero/appearance wording never counts as one — else 400 `concept_not_castable` with the reason) and, for a cast concept (`generated_images[c].cast`), a consent other than the one it was cast with (`generated_images[c].consent_id`; else 400 `same_person_as_cast`, before the cache lookup and the daily cap). a swap also needs the cast person's consent still active (else 409 `concept_not_ready` "Original image is no longer available"), and the base image (`generated_images[c].gcs_uri`) must sit directly in the run's own output folder in the bucket (`shares.output_prefix` / `source_path`; else 400 `image_outside_bucket`) and still exist (read at POST, ≤ 20 MB; missing → 409 `concept_not_ready` "Original image is no longer available", before the daily cap). `key = sha256(VARIANT_KEY_VERSION|photo_uri|image_generation_prompt|image model)[:12]` (`VARIANT_KEY_VERSION` `v3` since edit mode, `v2` was the appearance line; older records keep their keys and stay listed); a `done` record is returned as a cache hit (`cached: true`), a live render is joined (concurrent duplicate POSTs for the same session/concept/person are claimed synchronously before any await, so they render and count once). Otherwise a detached task (strong refs, like `/runs`) waits on a process-wide `asyncio.Semaphore(VARIANT_RENDER_CONCURRENCY)` (default 1) and edits through `creative_agent.render_concept.render_edit` (for swaps **and** adds): contents `[creative_agent/person_edit.py EDIT_INSTRUCTION ("Replace only the main person … Keep everything else in image 1 exactly as it is …") + the `unwanted_logo` strictness line + the ignore-reference-text line, "Image 1 (original ad):", <original>, "Image 2 (person):", <consent's photo>]` via `image_tools._render_person_image` (`ALLOW_ADULT`, `config.image_size`), aspect ratio = the allowed ratio nearest the original's pixel size (`person_edit.nearest_aspect_ratio`; the concept's ratio if unreadable); the run's other references are not sent. Image QA gets the concept (with the hero line plus `VARIANT_APPEARANCE_LINE`, QA context only — never sent to the image model), the person photo (likeness) and the original (`original_image` → the variant-only **composition check**, rule "composition changed", not critical); a failing likeness or composition repeats the edit of the original with `correction_text` appended (bounded like base renders). Engine renders and the render-parity golden are unchanged. **No fresh-render fallback** (a safety block → `rejected` + reason). Right before upload the variant's URI is appended to the consent's `person_renders` and, for a swap, to the cast person's consent too (`person_refs.record_renders`, which also re-checks each consent: revoked mid-render → `failed` / `consent_revoked`, nothing stored); a revoke of either during the upload deletes the object again. The kept image goes to `{gcs_folder}/{agent_output_dir}/variants/<owner slug>/<concept slug>/<key>.png` (blob metadata `consent_id` = the new person's consent, plus `source_consent_id` = the cast person's consent for a swap; `Cache-Control: private, no-store`; `gcs_folder` / `agent_output_dir` must be single safe segments, else 400 `invalid_output_folder`). State: `person_variants[concept][key] = {status: queued|rendering|done|failed|rejected, gcs_uri, qa, attempts, consent_id, source_consent_id, created_at, reason}`, written by events whose `state_delta` holds ONLY `person_variants` (re-read under a per-session lock); `final_visual_concepts`, `generated_images` and `_generated_artifact_keys` are never touched. Per-user daily cap `VARIANT_DAILY_CAP` (default 10; 429 `variant_cap_reached`): renders started today by this api process for the user, or today's variants in the session state if higher (per process, resets on restart, like the `/runs` duplicate guard). `GET /variants/{user}/{app}/{session}` → `{variants: {concept: {key: record}}, castable: {concept: {ok, reason, code, style, mode, cast_consent_id}}, person_safe_styles: [...]}` (a pending record with no live task reads `failed` / `interrupted`; `castable` covers every concept in `final_visual_concepts` and runs the same `variants.castability` checks as the POST — `code` `not_ready` / `style_not_person_safe` / `no_human_subject` / `not_castable`, a plain-language `reason`, `style` = the canonical family or the raw `visual_style`, `mode` `swap` (cast base image; `cast_consent_id` = its consent, the caller's own) or `add`). The panel reads it on open: when `castable[concept].ok` is false, **Render preview** is disabled with `aria-describedby` pointing at a muted note (`lib/variants.ts` `castabilityNote`: a style refusal reads "Personalised previews work on person-safe styles (<person_safe_styles>). This creative is <style>.", any other refusal shows the `reason` as given); until the GET has loaded (or against an api without `castable`) the button stays enabled and the POST explains a refusal. The panel polls it every 5 s while queued/rendering (stopped on unmount, or after 6 consecutive misses — an error or a missing record — with a Retry button), then shows base and preview side by side (`/api/gcs` owner-scopes `variants/<slug>/`) with the image check and the note "Personalised preview — not used in experiments or share links". Variants are never judged, rated, shared or deployed: `/shares` refuses any `person-refs/` / `variants/` image (400 `person_image`, shared `person_refs.is_person_image`), `experiments.snapshot_arms` never reads `person_variants`, refuses a `person-refs/` / `variants/` image (400 `person_image`); a cast creative is an arm only while its `generated_images[c].consent_id` is an active consent of the caller (`person_refs.active_consent`, else 400 `consent_not_active`; store error 503 `consent_unavailable`; the arm records `consentId`, and revoking the consent stops the experiment via the revoke hook `experiments.stop_experiments_for_consent`; experiment pages show "Image removed (consent revoked)" for such an arm, `arm-image.tsx`); the Deploy panel lets cast proofs be picked (the api decides). Quota: variants share the image model with live runs (the quota API lists 2 images/min, but `gemini-nano-banana-2.1` measured ~12/min sustained on 2026-10-13; renders back off on 429). Revoking the consent (or, for a swap, the cast person's consent) deletes the variant (see Person share scope + revoke cascade). Person photo URIs are never logged or returned.
### Person share scope + revoke cascade

- **Person share scope + revoke cascade (plan PR 4)**: **Shares:** `shares.http_create_share` resolves the run's cast consent ids (`share_snapshot.cast_consent_ids`) with `person_refs.active_consent(caller, id)` (store error → 503 `consent_unavailable`, before anything is written) and passes the records to `build_snapshot(..., consent_lookup=)`; a cast concept (`generated_images[c].cast`) is included only when its consent resolves to a record with `allow_public_share is True` (no lookup / no `consent_id` / revoked / another owner's → never). A slate share leaves the others out and returns `skipped: [{concept_name, reason: "person_not_shareable"}]` in the create response (the share dialog shows "N creative(s) showing a person were left out (their consent doesn't cover public links)." via `lib/shares.ts` `skippedNotice`); naming one is a 400 `person_not_shareable`. The included consents go on the row (`creative_shares.person_consent_ids ARRAY<STRING>`, ALTER migration in deployment/README.md), never into the snapshot. **Hardening:** share sources must sit directly in the run's own output folder (`shares.output_prefix`: `{gcs_folder}/{agent_output_dir}/`, safe segments like the variants path, else 400 `image_outside_bucket`); each source object's blob metadata `consent_id` is read before publishing and a set id not in the share's `person_consent_ids` is a 400 `person_not_shareable` (so a cast render whose state was seeded `cast: false` can't be published); the re-encoded images under `shares/` are fresh uploads with no custom metadata; after the row is stored every included consent is re-checked (still active + public) and a change revokes the new share (deletes `shares/<token>/`) → 409 `person_consent_changed` (closes the revoke-vs-create race). **Revoke cascade** (`DELETE /person-refs/{user}/{consent_id}`): mark revoked → re-read the record → `revoke_hooks` (`deployment/async_app.py` registers `shares.revoke_shares_for_consent`: every share of the owner whose `person_consent_ids` contain it, revoked ones too, is revoked and its `shares/<token>/` deleted; and `experiments.stop_experiments_for_consent`: every live experiment of the owner with an arm `consentId` = it is stopped through the stop route's teardown) → `person_refs.delete_renders` (every `person_renders` URI under the bucket, outside `shares/` / `person-refs/`, whose blob metadata `consent_id` or `source_consent_id` (a person swap edited from a render cast with it) still equals the consent; session state is client-seedable, so a recorded URI alone never deletes) → `person_refs.delete_session_renders` (every run recorded on the consent as a `session:<app>/<session_id>` entry in `person_renders`, written by `async_runs.record_person_session` at `start_run` after the consent check — store error → 503 `person_reference_unavailable`, nothing started — is read via the session service passed to `person_refs.configure(session_service=)`, and its `generated_images` / `person_variants` entries naming the consent (as `consent_id` or a swap's `source_consent_id`) are deleted, metadata-checked, and so is every object in its output folder `{gcs_folder}/{agent_output_dir}/` (safe segments like `shares.output_prefix`, else not listed; ≤ `MAX_FOLDER_SCAN_BLOBS` (500) listed, variants included) whose blob metadata `consent_id` / `source_consent_id` names the consent (a cast render that dropped out of `generated_images` when its concept was renamed and re-rendered); a deleted session is skipped; this covers runs that died mid-segment) → the photo; any failure → 502 `revoke_incomplete`, repeat the DELETE (idempotent). Cast renders are **not** saved as ADK artifacts (`image_tools._store_image` skips `save_artifact` when a `consent_id` is set: the api's artifact service is per-instance and unreachable from the revoke, and nothing reads image artifacts back; the results page uses the GCS image). Other renders' artifact copy is best effort (a failed `save_artifact` is logged and the GCS image kept), and `generate_image` writes every finished upload to `generated_images` in a `finally`, so a later failure never leaves a cast object in GCS outside state and the revoke cascade. **`person_renders`** (`person_refs_store.add_renders`, owner-guarded `UPDATE … ARRAY(SELECT DISTINCT …)`, revoked consents too): variants are appended before upload; cast base renders (uploaded by `image_tools` with blob metadata `consent_id` via `_save_to_gcs(metadata=)`) are appended by `async_runs._record_cast_renders` when a `/runs` segment ends (before every terminal marker, done/error/timeout; creative apps only; `cast_renders(state)`; 30 s bound, never fails the run). `person_refs.record_renders` re-checks the consent after appending and deletes the renders at once when it was revoked meanwhile. **Results page:** `ProofImage` (`proof-grid.tsx`, grid + proof detail) shows "Image removed (consent revoked)" when a cast creative's image fails to load (else "Image not rendered").

## Image-generation prompt guidance

Image-generation prompt guidance lives in `creative_agent/prompts.py` as `IMAGE_PROMPT_GUIDE` (a style-first prompting grammar for still ad images); visual agents must select a `visual_style` per concept rather than defaulting to photorealism. It is spliced into the drafter/critic instructions by string concatenation and must contain no `{...}` braces (ADK would treat them as state tokens — fill-in slots use `[square brackets]`). Image diversity (`docs/plans/2026-10-06-image-diversity.md`): each session gets a random stratified `style_shortlist` of 6 style families (`creative_agent/style_shortlist.py`, seeded once in `callbacks._set_initial_states`, read via `{style_shortlist?}` by the drafter/critic/finalizer, which pick 4 distinct families from it); the guide's palette entries are descriptors (when-to-use + cues), not fill-in templates to copy; in-image text is capped at 2 of 4 concepts (short headline/CTA; meme captions and comic speech bubbles are exempt); and an across-set composition rule allows at most one centred hero with varied camera distance. Each concept also carries a `trend_motif` and a `brand_cue` (a brand distinctive asset from the brief or `{brand_colors?}`; shared brace-free rules `VISUAL_CONCEPT_RULES` also require in-image text to be quoted exactly from the paired copy's headline/CTA and the brief's avoid list / fit_mode to be respected), and `callbacks.ensure_trend_and_product_callback` (`after_agent_callback` on `visual_concept_finalizer`, `visual_concept_fixer` and interactive's `visual_concept_reviser`, pure logic in `creative_agent/concept_guard.py`) appends the motif, `{target_product}` and/or the `brand_cue` to any final `image_generation_prompt` missing them, logging a warning. "Missing" is conservative token overlap, not a substring (`creative_agent/text_match.mentions`, brand-anchored; with a brand, the brand + every digit/all-caps model token also counts, so "PRS SE CE24" names "SE CE24 Electric Guitar"); intangible products get a softer branded-screen/logo cue. `concept_gate` then runs `concept_guard.concept_issues` (quoted in-image text that doesn't match the paired headline/CTA, empty `trend_motif`, >2 headline/CTA text concepts, >1 centred hero; meme/comic concepts exempt) and routes flagged concepts to one bounded `visual_concept_fixer` round (`CONCEPT_REVISION_ROUNDS`). Heuristic details: [docs/notes/creative-quality-gates.md](../../docs/notes/creative-quality-gates.md).
