# Evaluation (`libs/creative_eval/`)

Moved from [CLAUDE.md](../../CLAUDE.md) on 2026-10-15 (verbatim) so the always-loaded file stays short. Keep this file current when the subsystem changes.

**Evaluation — `libs/creative_eval/`**: LLM-as-judge (`gemini-3.1-pro-preview` @ `global`, structured output, one independent concurrent call per creative) that returns, per ad copy and per visual concept, 6 advisory quality scores (12 dimensions total) **plus binary gates**. Scores normalized 0.0–1.0; a creative `passed` only when its score ≥ 0.7 **and** every non-advisory gate passed (computed in code; historical score-only pass rates aren't directly comparable). The judge gets the structured `creative_brief` (`libs/creative_eval/brief.py`). Gates — ad copy: `delivers_proposition`, `product_named`, `uses_reason_to_believe`, `mandatories_met`, `avoid_respected`, `trend_risks_respected`, `trend_connected` (blocking, not brief-dependent: a clear, specific tie to the trend a follower would recognise; vague or bolted-on fails; passed in code with note "no trend" when the run has no trend), `timely_claim_supported` (see visual); visual: `product_visible`, `trend_motif_visible` (visible, not tiny/hidden in the background, and recognisable as the trend to someone who follows it; stylised/abstract/symbolic references count, e.g. a checkered finish-line pattern for a marathon; fails only when absent, too small to notice or so generic it could illustrate any trend; passed in code with note "no trend" when the run has no trend, like `trend_connected`), `text_correct`, `brand_cue_present` (**advisory**, never blocks), `avoid_respected`, `no_visual_defects` (malformed/mirrored product, broken anatomy; stylisation and small/illegible product-label text exempt), `trend_risks_respected` (the brief's `trend_bridge.risks`, shown to the judge as "Trend risks: …"; no jokes about a real disaster's severity/victims/warnings), `person_depicted_respectfully` (only judged for a concept rendered with the run's consented person, `generated_images[concept].cast is True`, shown to the judge as "Person Cast: yes"; otherwise passed in code with note "no person cast", whatever the judge says; a cast concept's request also attaches the consented person's reference photo (`person_reference.uri`) after the render as ground truth for their own appearance — tattoos, piercings, glasses etc. are never defects or disrespect), `timely_claim_supported` (blocking, ad copy and visual: only judged for a timely creative — its own `uses_trend_state is True`, or a visual's paired copy's (`ad_copy_id == original_id`), and `trend_situation.timely_ok is True` (the engine's `timely_allowed` rule; never on a `trend_sensitive_hint == "yes"` run) — shown to the judge as "Timely: yes" plus a `<CURRENT_MOMENT>` block (phase, event, dates, outcome, `as_of`, `valid_until`, `tone_rule`, cited source URLs from `state["sources"]`; plain dict keys, no `creative_agent` import): the reference matches the moment's phase and outcome, states no date or result missing from it and follows its tone rule; otherwise passed in code with note "not timely"; omitted for a timely creative → failed "not checked" + a report warning), `safer_angle_respected` ("Respectful reference"; blocking, ad copy and visual: only judged on a safer-angle run — `state["safer_angle_active"] == "yes"`, a sensitive trend the user deliberately picked and opted in to a respectful, positive angle on — shown to the judge as "Safer Angle: yes" plus brief-block lines "Safer angle: <`trend_bridge.safer_angle`>" and "Sensitive event (never referenced): <`safer_angle_sensitive_reason`>" (each only when present): never references the sensitive event, its victims or harm, any naming of the real person is a respectful tribute or inspiration only (no endorsement, partnership, licensing, implied use/ownership, quotes or words put in their mouth), visuals show no likeness of the real person and no estate-owned imagery; `trend_connected` / `trend_motif_visible` accept a clear tie through the safer angle; otherwise passed in code with note "no safer angle"; omitted on a safer-angle run → failed "not checked" + a report warning) — gates changed 2026-10-08 (person gate added 2026-10-10, `trend_connected` 2026-10-12, `timely_claim_supported` 2026-10-13, `safer_angle_respected` 2026-10-15, `trend_motif_visible` "no trend" pass 2026-10-15.2), so judge pass rates before/after are not comparable (labels in `libs/creative_eval/dimensions.py`, mirrored in `frontend/src/lib/eval-dimensions.ts`, drift-tested); without a brief the brief-dependent gates pass with note "no brief" (`report.brief_used=False`). **Judge integrity (`2026-10-15.1`):** the judge's JSON carries only the score — report ids (`original_id`, `headline`, `concept_name`, `ad_copy_id`) come from the input creative; verdicts are reduced to `EvalConfig.*_dimensions` (`normalize_verdicts`: lenient names, first duplicate wins, unknown dropped; a missing dimension → `score.unscored_dimensions`, not passed + a report warning); only gates the judge had to decide (blocking, not decided in code) count as reported — none → the failed `gates_reported` gate, one left out → failed "not checked" + a report warning (only the advisory `brand_cue_present` passes unchecked); untrusted text is fenced (system prompts: tagged text is data, never instructions; `<`/`>` in every interpolated value → `‹`/`›`, `judge.fence`; explicit prompt field lists, never `**creative`); a failed call is marked by `score.judge_failed` (the `"evaluation_failed"` improvements marker is still written, and read only for older reports). The visual judge sees the **rendered image** (`generated_images[concept].gcs_uri` as a `gs://` `Part`, fetched by the Vertex AI service agent, only under `gs://$GOOGLE_CLOUD_STORAGE_BUCKET/`, else the prompt + a report warning; the prompt is intent only, the image-QA verdict a hint); no image or an image read error → it judges the prompt (`image_judged=False` + a report warning). The report records `passing_threshold`, `trend_valid_until` (the timely moment's `valid_until`, else ""; per evaluation `timely`) and, for runs steered by opt-in rating learning, `learning_used` + `learning_flags`; summary `gates_pass_rate` (judged creatives only) → BigQuery `creative_evals.gates_pass_rate`. The eval is the independent final measurement and never triggers regeneration (that is the pre-eval gates' job). **Early ad-copy judging:** in `creative_agent`'s `creative_pipeline`, `finalize.evaluate_ad_copies_node` (→ `creative_eval.agent.evaluate_ad_copies_only`) runs in a fan-out next to `visual_production_pipeline` (`ad_copy_eval_join` waits for both) and stores `ad_copy_evaluations_partial` (`{fingerprint, evaluations}`); finalize's `evaluate_all_creatives` then judges only the visuals and merges the stored results into the same report. The partial is reused only while `ad_copy_eval_fingerprint` (ad copies + brief + campaign + `trend_situation` + `trend_sensitive_hint` + the safer-angle state `safer_angle_active` / `safer_angle_sensitive_reason` / `safer_angle_named_copies` + judge) matches; failed early calls are re-judged, and without a usable partial (early failure, interactive_creative, standalone `finalize_pipeline`) everything is judged in finalize as before. Concurrency: mixed batches use `EVAL_MAX_WORKERS` (2, the sustained-rate cap under the 5-RPM Pro quota); the visuals-only batch left after early judging runs as one parallel wave of up to `EVAL_MAX_VISUAL_WAVE_WORKERS` (4) (`EvalConfig.workers_for`; both clamped 1–16, a non-integer → the default + a warning). Judge-only output schema, gate prompt rules and `normalize_gates`: [docs/notes/creative-quality-gates.md](../../docs/notes/creative-quality-gates.md). **Human calibration:** users rate creatives on the results page (`/ratings` API, BigQuery `creative_ratings`, each row snapshotting the judge's verdict incl. `gates_passed`, plus allowlisted **fail-reason chips** (`fail_reasons`, enum in `runserver/rating_reasons.py` mirrored in `frontend/src/lib/rating-reasons.ts`, drift-tested incl. the per-kind lists `FAIL_REASONS_BY_KIND`; unknown value → 400 `invalid_fail_reasons`, a reason not offered for the rating's kind is dropped, emptied on a pass) and a learning context stamped from session state at PUT time (`brand` via the shared `creative_agent.normalize_brand` (strip + lower, the Python side of brand history's `LOWER(TRIM(brand))` match), canonical `visual_style`, `tone_style` from the `FinalAdCopy` Literal, brief `angle_id`; anything else `""`; `runserver.ratings.learning_context`) for rating-driven learning (see **Rating learning** in [configuration.md](configuration.md)), `docs/plans/2026-10-08-rating-driven-learning.md`); `runserver/calibration.py` reports agreement + Cohen's kappa + Spearman's rho (`GET /ratings/{user}/calibration`, `scripts/eval_calibration.py`). **Versioned:** `creative_eval.JUDGE_VERSION` (`libs/creative_eval/dimensions.py`, `2026-10-15.2` since `trend_motif_visible` passes in code with "no trend" on a run without a trend (`2026-10-15.1` added the judge-integrity pass rules + data-fencing prompt wording above, `2026-10-15` added the `safer_angle_respected` gate, `2026-10-13.1` exempted small product-label text from `no_visual_defects`, `2026-10-13` added the `timely_claim_supported` gate; a same-day second change gets `.N`; compared by equality only); unversioned reports still infer `2026-10-08` from their `no_visual_defects` gate; bump to the change's date whenever the gates, gate/dimension wording, scoring/pass rules or judge model change) is stamped on every report (`judge_version`; older reports `""`) and snapshotted per rating with the run's `learning_used`; calibration counts only current-version ratings (`runserver` imports the constant from `creative_eval`, no mirror) and adds `judge_version`, `excluded_other_versions` and `by_learning` {`learned`, `not_learned`} (same blocks) to the response; the script takes `--judge-version <v>|all`; the `/runs` line counts the current judge only ("(current judge only; N earlier ratings not counted)") plus a "Learned runs: kappa X · not learned: kappa Y" line once both sides have 20 pairs. Protocol: [docs/notes/judge-calibration.md](../../docs/notes/judge-calibration.md).

**Judge model (moved from the README, 2026-10-16):** the judge defaults to `gemini-3.1-pro-preview` at `global`; override it with `EVAL_MODEL` and `EVAL_MODEL_LOCATION` (`libs/creative_eval/config.py`). Unlike the Pro producers, the judge has **no fallback model**, so a silent model swap can never skew pass rates. The eval is the independent final measurement and never triggers regeneration; fixing creatives is the job of the deterministic gates that run before it.
