# Frontend (`frontend/`)

Moved from [CLAUDE.md](../../CLAUDE.md) on 2026-10-15 (verbatim) so the always-loaded file stays short. Keep this file current when the subsystem changes.

Next.js 16 (App Router) + TypeScript + Tailwind CSS + shadcn/ui. Light "proof room" theme with Archivo (see the design-system note below). Consumes the backend REST endpoints at `localhost:8000` — ADK's canned session/artifact CRUD plus the async-job `/runs` kick-off/poll/resume endpoints (served together by `deployment/async_app.py`).

**Deployment:** the frontend now ships to Cloud Run as two services — `trend-trawler-web` (Next.js standalone) and `trend-trawler-api`. The backend runs the **custom launcher `deployment/async_app.py`** under uvicorn (entrypoint `deployment/backend_entrypoint.sh`): it mounts ADK's canned FastAPI app (session/artifact CRUD, `getSession`, `list-apps`) **plus** the async-job `/runs` router from the flat `runserver/` package — both sharing one `VertexAiSessionService`. It **must** be deployed with `--no-cpu-throttling --min-instances 1` so detached runs keep CPU and aren't killed by scale-to-zero (see the async-run runbook). The backend is private; the same-origin `/api/adk` proxy reaches it with a metadata-server ID token (`roles/run.invoker`). The frontend is **IAP-gated** (domain-restricted to `jordantotten.altostrat.com` via Cloud Run direct IAP), and the backend uses **persistent Agent Engine sessions** via `SESSION_SERVICE_URI` (a dedicated `trend-trawler-sessions` Reasoning Engine). Both images are built by the repo-root `cloudbuild.yaml` (`gcloud builds submit --config cloudbuild.yaml --ignore-file deployment/cloudbuild.gcloudignore --substitutions=SHORT_SHA=$(git rev-parse --short HEAD)` (SHORT_SHA is required; buildx fails on an empty tag): parallel BuildKit builds with a registry layer cache, digests printed; optional `_DEPLOY=true` deploys at `--no-traffic` only) and deployed with `gcloud run deploy --image <digest>` + the usual traffic pin (`--source` still works, uncached). Runbook: [deployment/README.md → Frontend + api_server on Cloud Run](../../deployment/README.md#frontend--api_server-on-cloud-run).

**Public share viewer (`SHARE_MODE`, `docs/plans/2026-10-09-shareable-links.md`):** a third Cloud Run service, `trend-trawler-share`, runs the **same image** (deployed with `--image` = `trend-trawler-web`'s image digest, no separate build) with `SHARE_MODE=1` and is the **only public service** (`--allow-unauthenticated`; never add allUsers/IAP changes to web or api). The Next 16 **Proxy** (`frontend/src/proxy.ts` — the renamed Middleware; no matcher, env read per request; pure rules + headers in `lib/share-mode.ts`) then serves only `/s/<token>` + `/s/<token>/img/<n>` (token `[A-Za-z0-9_-]{16,64}`, n 1–2 digits), `/_next/static/*`, `/robots.txt` (`Disallow: /`, `app/robots.ts`) and `/favicon.ico`; everything else — every `/api/*` (`/api/gcs` would expose the whole bucket), every IAP page, `/_next/image` — is a plain 404, matched on the raw undecoded pathname. Share routes (also reachable behind IAP in normal mode as an owner preview) get `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`, `nosniff`, a per-request nonce CSP (`script-src 'self' 'nonce-…' 'strict-dynamic'`; `style-src 'unsafe-inline'` for React style attributes; `img-src 'self' data:`; `frame-ancestors 'none'`) and, on share pages only, `Cache-Control: no-store` (a cached page would replay its nonce; `lib/share-mode.ts` `shareHeaders(pathname)` leaves share images' Cache-Control to their route handler, since a Proxy header would replace the handler's). `lib/share-snapshot.ts` (server only) validates snapshot v1 (`isSnapshotV1`: allowlisted fields, capped strings, ≤ 4 creatives with `index` = position, eval only when `include_eval`) and reads only `shares/<token>/snapshot.json` / the image the snapshot names (`creatives[n].image`, exactly `<n>.jpg` or, for shares made before the JPEG re-encode, `<n>.png`; content type from the extension) from `GOOGLE_CLOUD_STORAGE_BUCKET` with the service's metadata-server token (`lib/gcp-auth.ts`); its SA `tt-share-sa` has `storage.objectViewer` conditioned to the `shares/` prefix. `SHARE_BASE_URL` makes `og:image` absolute. The root layout's `components/site-header.tsx` renders no header/nav on `/s/*`. Runbook: [deployment/README.md → Shareable links](../../deployment/README.md#shareable-links).

**Per-user authz (P3 trust model, `docs/plans/2026-09-29-p3-per-user-runs-authz.md`):** the proxy is authoritative; the backend only trusts it.
- **Proxy** (`frontend/src/lib/iap-identity.ts`, `user-scoping.ts`, `app/api/adk/[...path]/route.ts`): verifies the `x-goog-iap-jwt-assertion` (ES256, IAP issuer, audience = `/projects/N/locations/R/services/K_SERVICE` from the metadata server or `IAP_AUDIENCE`; requires `exp`/`iat`/`email`, `hd == IAP_ALLOWED_HD`; the spoofable `x-goog-authenticated-user-*` headers are never read) → normalized email (strip, lowercase, drop `accounts.google.com:`). Only allowlisted UI routes pass (else 404; segments with a decoded `/` or `\` or a non-identifier app name are refused); every path/body `userId` (clients send placeholder `me`) is rewritten to the caller, only `since`/`version` query params forwarded (plus a positive-integer `run` on `GET experiments/{u}/{id}/metrics|creatives`), and `X-TT-User` set. Ratings routes: `GET`/`PUT ratings/{u}/{session}` + `GET ratings/{u}/calibration` (session id must match `SESSION_ID_RE`). Share routes: `POST shares/{u}/{app}/{session}` (identifier app name, `SESSION_ID_RE`), `GET shares/{u}`, `DELETE shares/{u}/{token}` (`SHARE_TOKEN_RE` `^[A-Za-z0-9_-]{16,64}$`). Person-reference routes: `GET`/`POST person-refs/{u}`, `DELETE person-refs/{u}/{consent_id}` (`PERSON_REF_ID_RE` `^[A-Za-z0-9_-]{8,64}$`); these two are the only DELETEs the proxy forwards. On Cloud Run a missing/invalid JWT or unset `IAP_ALLOWED_HD` → 401; locally (no JWT, no `K_SERVICE`) it passes through unscoped (fail-open by design).
- **Backend** (`runserver/authz.py`, installed in `deployment/async_app.py`): trusts `X-TT-User` only alongside a verified Google ID token for `TRUSTED_PROXY_SA` (`tt-web-sa`; minted with `format=full` so it carries `email`) with `aud ∈ TRUSTED_PROXY_AUDIENCES`. Path/body `userId` ≠ trusted user → 403; missing/untrusted `X-TT-User` on a user-scoped route → 401; blocked canned routes (`/run`, `/run_sse`, `/run_live`, memory, agent-identity) → 404; a foreign session (`VertexAiSessionService` ownership `ValueError`) → 404.
- **Owner-only GCS paths (`/api/gcs`, `lib/person-paths.ts`):** run artifacts stay shared across users, but `person-refs/<slug>/…` (consented person photos) and `…/variants/<slug>/…` (personalised variants, PR 3) are served only to the user whose email slug matches (`emailSlug`, server-only via `node:crypto`: `<readable>-<h>`, readable = the trimmed lower-case email with `@` and `.` → `_`, h = first 10 hex chars of sha256(that email), so `a.b@x.com` and `a_b@x.com` stay apart; mirrors `runserver.person_refs.slug_for`, both checked against the shared golden `tests/fixtures/person_slugs.json`): `resolveUser` like the `/api/adk` proxy, reject → 401, another user or an owner-less path → 404, local → allowed; `Cache-Control: private, no-store`. Every other path is proxied unchanged (no identity check).
- **Modes:** `USER_AUTHZ_MODE=enforce` (default; refuses to boot without `TRUSTED_PROXY_SA` + `TRUSTED_PROXY_AUDIENCES`) | `observe` (logs `authz observe: would deny …`, blocked routes still 404); `TRUST_CLIENT_USER_ID=1` = trust the client `userId` (local dev only; refused when `K_SERVICE` is set).

**Design system ("proof room", `docs/plans/2026-10-02-frontend-proof-room.md`):** tokens in `src/app/globals.css` (`primary` #0077A8 is the only action colour; `mark-pass`/`mark-fail`/`mark-pending` status marks), Archivo, sentence-case `FieldLabel`; no uppercase eyebrows, glass cards or entrance animations; mono only for code-like data.

**Pages:**
- `/` — Campaign input form (brand, audience, product, selling points, agent tiles: `trend_scout`, `creative_agent`, `interactive_creative`) plus a recent-runs sidebar; a trend carried over from a trend card whose `trendContext` is flagged sensitive shows an amber "Sensitive trend" alert (creative agents; cleared when the trend is edited) with an off-by-default "Look for a respectful angle" checkbox (`components/safer-angle-toggle.tsx`; seeds `safer_angle_opt_in: true` only when checked AND the context is sensitive, cleared with the trend, restored by Duplicate brief; shown as "Safer angle: On" in the run/results metadata, and the run/results pages show a muted "Safer angle: …" line, `components/safer-angle-line.tsx`, `lib/safer-angle.ts`; checkpoint 1 edits `trend_bridge.safer_angle`); trend cards show the same chip and carry the flag in `trendContextJson`
- `/people` — Person references (`app/people/page.tsx`, nav "People"): the caller's copyable upload prefix (`gs://<bucket>/person-refs/<slug>/`, from `GET /person-refs/{u}`'s `prefix`; the slug rule when the api has no bucket), the consent text (`lib/person-consent.ts`, drift-tested against `runserver/person_refs.py`), photo guidance above the form (`PHOTO_GUIDANCE` in `lib/person-refs.ts`: one front-facing head-and-shoulders photo, even light, ≥ 1024 px, not a collage/character sheet/group photo — why: `docs/notes/person-reference-calibration.md` → Photo guidance), a register form (photo `gs://` URI, name, who (me / someone who agreed), required adult attestation, optional public-share consent), and the caller's people (thumbnail via `/api/gcs`, public links yes/no, added, and for `low_resolution` people "Low resolution: previews may look softer. Re-register with a 1024 px photo.") with a confirmed **Revoke** ("Deletes the photo and every image made with it")
- `/runs` — Run history (brand, trend, agent, status, updated) with **Duplicate brief** to prefill a new run from an old one, plus a muted "Judge agreement" line (kappa + agreement % once 20 of your ratings are paired with a current-judge verdict, else "Rate N more creatives to calibrate the judge"; earlier-judge ratings noted, not counted; a second learned/not-learned kappa line; `components/judge-agreement.tsx`)
- `/run/[sessionId]` — Live run view: the page **polls** the async-job run (fire-and-forget kick-off + `GET /runs/.../{session}?since=N`) and shows a stage spine, a current-stage panel, outputs so far, and a collapsed technical log. Because progress is read from the persistent session log (not a browser-held SSE stream), a run **survives disconnect/reload/IAP re-auth** — reloading re-polls from `since=0` and replays; opening an existing run follows it without re-sending the kick-off message. Interactive-mode review checkpoints take over the main area; the trend pick (`ReviewTrends`) marks trends in `trend_flags` with an amber "Sensitive" chip (reason on hover + `aria-describedby`; `lib/trend-flags.ts`, `components/sensitive-chip.tsx`), still selectable, and selecting one shows a note that creatives never reference the event. Failure comes only from the poll status (`pollRun` throws on `error`); an error event in the log (a contained step error) is a muted non-blocking notice "A step reported an error and was skipped: …" (`lib/step-errors.ts`, 429 → friendly quota text), so the run keeps being followed.
- `/results/[sessionId]` — Contact sheet of creatives (image, headline, ad-copy/visual scores, sortable; a mark-fail "Check failed" chip when a blocking eval gate failed; on the timely creative (its concept or paired copy `uses_trend_state`) a mark-pass "Timely" chip ("valid until …" in title + sr-only) that turns mark-pending "Expired" once `trend_situation.valid_until` <= the wall clock (`lib/use-wall-clock.ts`, refreshed every minute; never `current_datetime`), mirrored by the proof detail's "Timely" row ("Expired on …") and the Deploy panel (still selectable, with a muted warning line "Its moment ended on …; fine for a simulation, but don't use it live.", `creativeDeployWarning`); a slate share's `timely_expired` skips get their own notice) with a proof-detail dialog per creative (a "Checks" section — pass/fail per gate, advisory ones labelled — above the "Quality (advisory)" dimension scores; `results/[sessionId]/eval-checks.tsx`; old gate-less reports render as before; then **Your rating**: pass/fail, on a fail optional kind-relevant fail-reason chips ("Why did it fail? (optional)", aria-pressed toggles), optional 1–5 score + note for the ad copy and the visual, optimistic save; `rating-control.tsx` via the dialog's `ratingSlot`; rated proofs get a muted "Rated" mark; a **Share this creative** button via the dialog's `shareSlot`; a **Personalise** panel via `personaliseSlot` for rendered creatives ("Swap person" on cast ones) — see Personalised variants), **Share slate** in the header and a **Shared links** section (this session's links: title, scope, created, "With checks" badge, Copy, confirmed Revoke) — share controls only for creative apps with rendered images (`components/share-dialog.tsx`: "Include judge checks and scores" (off), the never-shared notice, a non-blocking mark-pending note naming any shared creative's failed blocking checks (`failedChecksFor`), Create link → read-only URL + Copy (polite "Link copied") + Open, friendly per-reason errors (`lib/shares.ts`); a relative `/s/<token>` URL (no `SHARE_BASE_URL` on the api) is copied as given with a hint; `components/shares-list.tsx`), a mark-pending "Names a real person" chip on proofs whose paired copy id is in `safer_angle_named_copies` (proof detail: "Respectful tribute only. Check name and likeness rights before using this live."), plus artifacts, research PDF, evaluation report and session state
- `/s/[token]` — **Public share page** (no sign-in; `SHARE_MODE` service): `h1` "<brand> × <trend>", product subtitle, a keyboard-navigable Card / Feed / Story switcher (`ui/tabs`, `activateOnFocus`, view kept in `?view=`; Feed (`components/share/feed-post.tsx`) is a link-ad mock: header → caption as primary text above the image (truncated, real "more" button) → image → a full-width link bar `data-slot="feed-link-bar"` with brand, headline `h2` and body (each clamped to 2 lines, full text in the DOM) left and the CTA right (`data-slot="feed-cta"`, stacks full width below 360 px)), one `<article aria-labelledby>` per creative (a list for a slate), optional judge "Checks" (text pass/fail marks, advisory labels, score) only when the snapshot has `include_eval`, footer "Shared from Trend Trawler · AI-generated images"; `generateMetadata` gives Open Graph/Twitter previews (slate: "<brand> × <trend> — N creatives"; single: the headline; caption ≤ 160 chars; noindex). Images come from `/s/<token>/img/<i>` (route handler; streams the object the snapshot names, `<i>.jpg` as `image/jpeg`, older shares' `<i>.png` as `image/png`, `private, max-age=60`). Missing/revoked → `not-found.tsx` "This link is no longer available" (404)

Both the run view and results view also surface the optional visual art-direction inputs (the PR #114 visual-intent keys) read-only in a "Visual Direction" section alongside the campaign metadata — driven by `buildDisplayFields` + `VISUAL_DIRECTION_FIELDS` in `frontend/src/lib/utils.ts`; unset keys collapse to `""` so non-creative/no-intent runs show nothing.
