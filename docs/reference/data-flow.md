# Data flow (BigQuery, Cloud Storage, Pub/Sub + Cloud Tasks)

Moved from [CLAUDE.md](../../CLAUDE.md) on 2026-10-15 (verbatim) so the always-loaded file stays short. Keep this file current when the subsystem changes.

- **BigQuery**: Stores the daily trend digest cache (`trend_digest` — one row per (`refresh_date`, term list): `digest_id` (MERGE key, `stable_row_id(refresh_date, terms_hash)`), `refresh_date DATE`, `terms_hash`, `digest` (JSON `{items, flags}`), `models`, `created_at`; partitioned on `refresh_date` with a 30-day partition expiration; created from `deployment/bq_schemas/trend_digest.json`; shared across users and engines, public Google Trends data only), trend recommendations (`target_trends_crf`, incl. `trend_context STRING` — trend_scout's compact per-trend research JSON from `trend_scout/trend_context.py` (+ `sensitive` / `sensitive_reason` for a flagged term; the CRF orchestrator skips those rows), "" when nothing parsed; additive ALTER migration 2026-10-11 in deployment/README.md, run before deploying trend_scout + the CRF worker), creative results (`trend_creatives`), per-run evaluation summaries (`creative_evals` — one row per run incl. `gates_pass_rate`, joins `trend_creatives` via `creative_uuid`, links to the full report JSON in GCS; its legacy-named `research_gaps` column holds all run notes), human creative ratings (`creative_ratings` — one row per (session, creative, user), MERGE on `rating_id`, snapshotting the judge verdict incl. `judge_gates_passed` + `judge_source` gcs|state|none + `judge_version` + the run's `learning_used` (ALTER migration 2026-10-09), plus learning context `brand` / `visual_style` / `tone_style` / `angle_id` and `fail_reasons ARRAY<STRING>` (bound as an array parameter; created from `deployment/bq_schemas/creative_ratings.json`, ALTER migration in deployment/README.md); api-only, `RATINGS_STORE=bigquery|memory`), shareable links (`creative_shares` — one row per share `token`: `owner_user`, `app_name`, `session_id`, `scope`, `concept_names ARRAY<STRING>`, `include_eval`, `title`, `created_at`, `revoked_at`, `person_consent_ids ARRAY<STRING>` (consents of the cast creatives shared, for the revoke cascade; ALTER migration in deployment/README.md); created from `deployment/bq_schemas/creative_shares.json`; api-only, `SHARES_STORE=bigquery|memory`), person-reference consents (`person_references` — one row per `consent_id`: `owner_user`, `photo_uri`, `label`, `subject` self|third_party_with_consent, `adult_attested`, `allow_public_share`, `consent_text_version`, `created_at`, `revoked_at`, `person_renders ARRAY<STRING>` (cast base renders + variants made with the photo, for the revoke cascade), `photo_min_side INT64` (nullable, the photo's shorter side in px; ALTER migration in deployment/README.md); created from `deployment/bq_schemas/person_references.json`; api-only, `PERSON_REFS_STORE=bigquery|memory`)
- **Cloud Storage**: Research PDFs, rendered images, eval report JSONs, HTML galleries, session state JSONs, frozen share snapshots (`shares/<token>/snapshot.json` + `<i>.jpg` re-encoded images, long edge ≤ 1600 px; older shares `<i>.png` copies), consented person photos (`person-refs/<owner slug>/<file>`, uploaded out of band; owner-only via `/api/gcs`; 365-day lifecycle backstop in `deployment/cleanup/` (with the rest of the trend-trawler-only retention), revoke deletes)
- **Pub/Sub + Cloud Tasks**: the orchestrator's trigger topic (Eventarc, with a dead-letter topic); orchestrator → worker dispatch over the Cloud Tasks queue `creative-worker-queue` (the worker topic only on the one-release Pub/Sub rollback path)
