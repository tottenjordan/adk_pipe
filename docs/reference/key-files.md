- `runserver/async_runs.py` — async-job run model: `/runs` FastAPI router + pure helpers. Kicks off a **detached `asyncio` task** driving `Runner.run_async` to completion decoupled from the HTTP request, appends a terminal `__run_status` marker event on done/error, and serves poll (`GET ?since=N`) + resume endpoints. Replaces browser-held SSE so runs survive client disconnect. **Status:** only the terminal marker decides `done`/`error` (every failure path writes an `error` marker: uncaught exceptions incl. a root model error that escapes, the `RUN_MAX_SECONDS` timeout, cancellation; a crashed instance leaves none and the client's stall timeout covers it). In-pipeline error events (`error_code`/`error_message`, e.g. a model 400 a `FailSoftNode` contained) never flip a running run to `error`; the poll payload lists them as non-fatal `warnings` (`[{author, message}]`, deduped, ≤ 5, truncated). **Auto-continue:** if a segment ends cleanly on an empty root turn (no text/function call) with the app's completion key unset and no unanswered long-running checkpoint call (`should_auto_continue`), it re-prompts the same session with `AUTO_CONTINUE_MESSAGE` before writing `done`; likewise (creative apps only) when the root's last function response in the segment is a NodeTool error result (`Error running node …`) with the completion key unset, with `AUTO_RETRY_MESSAGE` so the root re-calls the failed pipeline (`auto_continue_reason` → `empty_turn` | `pipeline_error`, same budget). This happens inside the same task and `RUN_MAX_SECONDS` budget, records `__auto_continues` in state, and is capped per segment by `RUN_MAX_AUTO_CONTINUES` (default 2, clamped 0–3). Creative apps count as finished only at `finalize_done` (set by `finalize_pipeline`'s terminal node on every path, even with no eval report or a failed eval BQ write), not at `eval_report_gcs_uri` / `eval_bq_row_uuid`.
- `runserver/ratings.py` / `runserver/ratings_store.py` / `runserver/calibration.py` — human creative ratings: `/ratings` router (PUT/GET per session, calibration; creative_key validated against session state, judge fields from the run's GCS report — only `gs://$GOOGLE_CLOUD_STORAGE_BUCKET/.../creative_eval_report.json` ≤ 5 MB, else the client-seedable state copy — recorded in `judge_source` gcs|state|none; fail soft; `scripts/eval_calibration.py` counts only `gcs` rows unless `--include-all`), BigQuery store fails startup on Cloud Run without the BQ env, BigQuery/in-memory store (`RATINGS_STORE`, `BQ_TABLE_RATINGS`), pure kappa/Spearman maths
- `runserver/person_refs.py` / `runserver/person_refs_store.py` — person-reference consent registry (plan `docs/plans/2026-10-09-person-reference.md`, PR 1): `POST /person-refs/{user}` (body `{photo_uri, label, subject, adult_attested, allow_public_share, consent_text_version}`; `photo_uri` only `gs://$GOOGLE_CLOUD_STORAGE_BUCKET/person-refs/<slug_for(user)>/<file>.(jpg|jpeg|png|webp)` else 400 `invalid_photo_uri`; object HEAD must be `image/*` ≤ 10 MB else `photo_unreadable`; `adult_attestation_required`, `stale_consent_text` (≠ `CONSENT_TEXT_VERSION`), `invalid_subject`, `invalid_label` (1–80); same active photo → 409 `already_registered`; ≤ 50 active → 429; no bucket → 503; then the photo is downloaded and sized with Pillow in a thread: undecodable → `photo_unreadable`, shorter side < `PERSON_PHOTO_MIN_SIDE` (env, default 512, clamped 256–4096) → 400 `photo_too_small`) → `{consent_id, photo_uri, label, subject, adult_attested, allow_public_share, consent_text_version, created_at, photo_min_side, low_resolution}` (`low_resolution` = `photo_min_side < 1024`; records without a size read `null` / `false`); `GET /person-refs/{user}` → `{person_refs, prefix, consent_text_version}` (records missing `photo_min_side` are sized lazily and cached via a guarded `UPDATE … WHERE photo_min_side IS NULL`; best effort, ≤ 10 s, a failure leaves `null`); `DELETE /person-refs/{user}/{consent_id}` revokes (204; 404 if not the owner's), runs `revoke_hooks` (the share cascade), deletes the recorded `person_renders` (metadata-checked) and then the photo (cleanup failure → 502 `revoke_incomplete`, retry the DELETE). Helpers: `slug_for(user)`, `active_consent(owner, consent_id)`, `record_renders(owner, consent_id, uris)`, `render_path`, `delete_renders`. Person photo URIs are never logged
- `runserver/variants.py` — personalised variant previews (plan PR 3, UI only): `POST` / `GET /variants/{user}/{app}/{session}`, detached renders behind `VARIANT_RENDER_CONCURRENCY` with a `VARIANT_DAILY_CAP`, results in `person_variants` + `…/variants/<slug>/` (details in [configuration.md](configuration.md) → Personalised variants); the default renderer `render_variant` is swappable via `configure(renderer=…)` for tests
- `creative_agent/render_concept.py` — `render_concept(concept, *, aspect_ratio, references, person, strictness, qa, brand, target_product, budget, fallback_without_person, pacing) -> RenderResult(image_bytes, mime, attempts, qa, qa_issue, cast, rejected_reason, concept, qa_unavailable)`: one concept's render (reference block, person part + `ALLOW_ADULT` + typed block fallback, QA + bounded re-render) without a `ToolContext`. `generate_image` runs it as one task per concept sharing a FIFO render lock, the per-run budget and `RenderPacing` events (first renders in concept order, QA overlapping the next render, budget claimed in concept order, uploads after all renders, in parallel; `generate_image` = `_plan_renders` → `_run_pipelined` → `_persist_results`; the QA re-render loop `_rerender_loop(QAContext, render_fn, budget)` is shared with `render_edit`); `render_edit(base_image, person, concept, *, aspect_ratio, strictness, qa, brand, target_product, budget)` is the variants' edit mode (edit the original render so only the person changes; `person_edit.edit_contents`, `ALLOW_ADULT`, no fallback, QA with likeness + the composition check vs the original, re-render = the same edit + correction). Behaviour parity is pinned by `tests/test_render_parity.py` (a golden recording of the pre-refactor requests, QA calls, uploads and state)
- `runserver/shares.py` / `runserver/share_snapshot.py` / `runserver/shares_store.py` — shareable links (owner side; plan `docs/plans/2026-10-09-shareable-links.md`): `POST /shares/{user}/{app}/{session}` (body `{concept_names?: [str] (../../1–4), include_eval?: bool}`; session ownership like `/ratings`, foreign → 404) freezes an allowlisted snapshot (v1: brand/product/trend + per creative `index, image, aspect_ratio, alt, visual_style, headline, body, caption, cta, tone` and, only with `include_eval`, `eval` {passed, score, checks [{kind, gate, label, passed, advisory}], copy, visual}; never prompts/rationales/notes/emails/ids; concepts paired with copy like `eval-matching.ts`), server-side re-encodes the images (`generated_images[concept].gcs_uri`, only under `gs://$GOOGLE_CLOUD_STORAGE_BUCKET/`, else 400 `image_outside_bucket`; download → `runserver/share_images.py` `to_share_jpeg`: RGB progressive JPEG q85, long edge ≤ 1600 px LANCZOS, never upscaled, no metadata, in a thread) to `shares/<token>/<i>.jpg` (`image/jpeg`; snapshot `image` = `<i>.jpg`) + writes `snapshot.json`, then records the share (`creative_shares`); partial failure → rollback + 502; ≤200 active shares per user (429); cast creatives only with public-share consent (`skipped` in the response, row `person_consent_ids`; `revoke_shares_for_consent` is the consent-revoke hook); a timely creative whose moment has ended (`runserver/timely.py` `timely_expired`: `uses_trend_state` on the concept or its paired copy, `trend_situation.timely_ok`, `valid_until` ≤ the api's wall clock, pinned by `tests/fixtures/timely_expiry.json`) is left out the same way (`skipped` reason / 400 `timely_expired`). `GET /shares/{user}` lists active shares (`{token, url, title, scope, include_eval, concept_names, app_name, session_id, created_at}`), `DELETE /shares/{user}/{token}` revokes (deletes `shares/<token>/`; 404 if not the owner's). URL = `$SHARE_BASE_URL/s/<token>`. The public viewer is `trend-trawler-share` (`/s/[token]`); the owner UI is on the results page (Share slate / Share this creative / Shared links)
