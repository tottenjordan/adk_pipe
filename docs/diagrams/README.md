# Agent Architecture Diagrams

Per-agent ADK architecture diagrams generated with the PaperBanana MCP pipeline
(`gemini-3.1-flash-image`), in the style of official Google Cloud documentation.
Each shows the agent/graph composition (ADK 2 graph `Workflow`s exposed as
`NodeTool`s, `AgentTool` wrapping, `RetryUntilKeyNode` retry wrappers) and the
per-agent tooling. The `trend_scout` and `creative_agent` diagrams were regenerated
2026-09-29 for the P2 graph-Workflow migration (no more Sequential/Parallel/RunIf agents);
the `interactive_creative` diagram was added 2026-09-29. The `creative_agent` diagram was
regenerated again 2026-10-08 for the creative-quality gates (it now also covers the interactive
variant and human calibration), and the `interactive_creative` and `creative_eval` diagrams plus the
three creative workflow diagrams were regenerated the same day (#263–#280: structured brief,
`brief_gate` / `copy_gate` / `concept_gate`, post-render image QA, eval gates on rendered images,
brief-review checkpoint, human ratings). The pre-gates versions are kept in [`archive/`](archive/)
and linked from each row. On **2026-10-12** the `trend_scout`, `creative_agent`, `interactive_creative` and `creative_eval` diagrams, the three creative workflows, the frontend app diagram and the live Cloud Run topology + auth flow were regenerated for the later work (trend-state awareness, rating learning, shareable links, person references, the share service, the P3 authz flow); each row links its previous version.

## Infrastructure Diagrams

Batch fan-out diagrams for the two Cloud Run services built from the one CRF image
(`cloud_functions/creative_fanout/`): the orchestrator is triggered by Pub/Sub via
Eventarc and reaches the worker through a Cloud Tasks queue (since the 2026-10-14
cutover; the worker no longer has an Eventarc trigger), and the worker runs the
deployed `creative_agent` on Vertex AI Agent Engine. Both diagrams were regenerated
2026-10-14 for the Cloud Tasks transport and the fenced row-state model.

| Diagram | Scope | Highlights |
|---|---|---|
| ![crf fan-out](crf_fanout_system_architecture.png) | System (breadth) | **Regenerated 2026-10-14** for Cloud Tasks delivery. Dispatch: `trend_scout` rows in BigQuery `target_trends_crf` → Pub/Sub `creative-eventarc-topic` (with its dead-letter topic, now the only one in use) → Eventarc → orchestrator `creative-trawler-crf`: 1 reap stale `PROCESSING`, 2 select ≤ N non-sensitive rows (`CRF_MAX_ROWS_PER_RUN`, default 3), 3 mark `QUEUED` by row key (`uuid`, `target_trend`), 4 enqueue one HTTP task per row (deterministic task name) → create task. Run one row: Cloud Tasks queue `creative-worker-queue` (1 at a time, 30-min dispatch deadline, 5 attempts) → HTTP POST + OIDC → worker `creative-worker-crf` (`agent_worker_task`; engine from `CREATIVE_AGENT_ENGINE_ID`) → fenced lock `QUEUED → PROCESSING @n` → re-read row (sensitive → `FAILED`) → Vertex AI Agent Engine `creative_agent` (session → stream) → `finalize_done?` (poll; one retry message only on an end-of-invocation signal) → `PROCESSED` / `FAILED` / requeue (fenced) → delete session (best effort); the worker answers 200 = done, 503 = retry. Sinks: `target_trends_crf`, `trend_creatives`, `creative_evals`, Cloud Storage (images, reports, gallery). Previous (2026-09-29, Pub/Sub + Eventarc worker) version: [archive/crf_fanout_system_architecture_2026-09-29.png](archive/crf_fanout_system_architecture_2026-09-29.png) |
| ![crf worker](crf_worker_reliability_deepdive.png) | Worker (depth) | **Regenerated 2026-10-14.** Row state machine (BigQuery `target_trends_crf`, row key `uuid` + `target_trend`): `NULL` → (orchestrator marks) `QUEUED` → (worker lock: compare-and-set, attempts n → n+1) `PROCESSING @n` → `PROCESSED` (`finalize_done`) or `FAILED` (not finished / sensitive / gone); back to `QUEUED` by requeue (session not started) or the reaper (stale `PROCESSING` → `QUEUED`, `FAILED` at max attempts); every write is guarded by the from-state and the fencing token n (0 rows changed = lost fence, nothing written). One task, one worker run: Cloud Tasks delivers the task (at least once) → worker `agent_worker_task` (deadline from request start) → fenced lock (duplicate → no-op) → re-read locked row → Agent Engine session (create → stream) → `finalize_done?` (poll while events append; one retry message only on an end-of-invocation signal; idle 600 s → give up) → `PROCESSED` write (retried, never `FAILED`) → delete session (best effort). Response to Cloud Tasks: **200 OK** for `PROCESSED`, `FAILED`, requeued, lost lock, malformed or unrunnable task (task done); **503** for an error before the row status was written (e.g. a BigQuery lock error), which Cloud Tasks retries (60 s → 600 s backoff, max 5 attempts). Previous (2026-07-13, Pub/Sub ACK/NACK) version: [archive/crf_worker_reliability_deepdive_2026-07-13.png](archive/crf_worker_reliability_deepdive_2026-07-13.png) |

## Regenerating

Diagrams are generated via the `paperbanana-figures` skill (PaperBanana uses the Gemini
Developer API, a separate quota pool from the pipeline's Vertex AI image quota). Superseded
versions are moved to [`archive/`](archive/) with their date, never deleted. To tweak a
label without a full regenerate, use `continue_diagram(run_id=..., feedback=...)`.
